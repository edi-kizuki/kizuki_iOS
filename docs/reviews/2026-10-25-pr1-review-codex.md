## Explicitly deferred prototype contracts

The v2.1 client baseline (§3.2) explicitly adopts this prototype and requires contradictory fixture expectations to be rewritten with the implementing slice. These are therefore recorded as follow-up obligations, not additional merge-blocking findings for the foundation PR:

- Block/unblock currently restores the accepted-request-derived Crew and chat (`FixtureBackend.swift:96`, `AppStore.swift:67`, `PrototypeStoreTests.swift:53`). A native probe confirmed this. B07/B10 must end the connection permanently; unblock must require fresh acceptance and a new conversation. The existing positive restoration assertion must change.
- Remove from Crew currently deletes the conversation (`FixtureBackend.swift:84`) and mutates accepted requests to ended. A native probe found three historical messages became no conversation. Decision 62/v2.1 requires read-only retained history, immutable accepted requests, a separate ended connection, pending-request withdrawal, membership removal and the directional 30-day cooldown. B07/B08 must implement these together. The current confirmation copy and tests are not evidence of compliance.
- Accepting a join currently creates Crew/chat without adding project membership; native probe confirmed no member row change. B07 must implement membership/seat changes atomically with acceptance.
- Short-video fixture durations include 27/45/58 seconds and the test permits 60 (`FixtureData.swift`, `PrototypeStoreTests.swift:126`), while decision 63 caps uploads at 15 seconds. B12/VF12 must replace these fixtures/assertions and implement 15 s / 720p / 15 MB validation. No real video playback/upload was reviewed as working.
- Feature mutations often suppress repository errors and optimistically announce success (for example RequestComposerView sends then sets sent=true regardless of AppStore.lastError). Before live repositories are composed in B01 and subsequent slices, return mutation results, display failure, retain input and serialize/version profile saves. The current non-throwing fixture backend does not verify network-failure behavior.
