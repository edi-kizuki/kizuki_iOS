## Implementation

- Protocol-typed `Dependencies.live(...)` and Debug-only `.fixture`; Debug defaults to fixtures. `-live` uses a shared SDK client and the live session root. Fixture screen routing is ignored in live mode. The existing tab shell is shared; fixture launch/gallery code stays Debug-only.
- `AppSession.refreshProfile()`, server-derived eligibility/onboarding/account gates, explicit verification/recovery events, and per-account `SessionScope`. Token refresh preserves the scope and recovery gate. Switching accounts awaits channel/cache cleanup, cancels tasks, and rejects stale profile/sign-out responses.
- Supabase Swift remains pinned to 2.55.4. Own-profile reads project lifecycle fields plus confirmed `legal_acceptances`; the pre-B02 schema can reject this projection and the app shows a retryable failure. No schema changes or invented fallback data. All 19 pending feature repository calls throw typed not-yet-available errors. B04/B05 implement the entry/recovery/eligibility/onboarding forms; B01 displays honest placeholders.
- Runtime production refusal, Debug-only local loopback, exact staging allowlist. Release post-build scans app symbols (including sibling dylibs) for fixtures. Non-Debug configuration checks cover local/production/unapproved staging refusal and approved staging acceptance.
- Swift contract replay reads every bundled `ios/Tests/Contracts/*.json`; B01 has zero recordings, as allowed. Synthetic success/error cases exercise the harness; real recording/normalization arrives with B02+.
